# Source acquisition and explicit review

Acquisition records upstream bytes; it does not approve a licence. An OFL heading, filename, or repository API licence label is insufficient to decide the applicable grant, licence choice or Reserved Font Names (RFNs).

## Current corpus

The original `manifests/corpus.lock.json` and `configs/sources.json` remain byte-for-byte unchanged because the trained artifacts/results bind to their hashes. Some legal annotations in that schema-1 lock were automatically generated by the initial acquisition implementation. They are historical annotations, **not current authorization**. In particular, do not treat `approved_usage`, `license_selected` or the old generic RFN sentence as an independent review.

The authoritative replay gate is `manifests/source-review.json`: 14 explicit current-corpus agent review decisions linked to all 54 exact asset identities. It binds the original config/lock hashes and versions, each repository/commit/path/hash/size, and the exact notice hash plus a reviewed affirmative-grant excerpt. Dyuthi, Meera and Rachana explicitly offer OFL alternatives; those choices are recorded, rather than falsely excluding their dual-licensed assets. Original notices are retained unchanged.

These decisions approve only local rendering/research for this pinned corpus. RFNs are **not assessed for export** (`names: null`), rather than guessed absent. Checkpoint redistribution and derivative-font release are not approved by this review. Agent review evidence is inspectable; it is not a legal opinion or endorsement by upstream authors.

## Replay

With `PYTHONPATH=src`, run `python scripts/acquire.py`. Before network access or writes, replay requires exact family/asset membership and order, source identity, supported schema versions, locked config/review fingerprints, source URL/local-path consistency, and a matching explicit decision for every asset. Missing assets or reviews fail closed; there is no `expected=None` acceptance path. Downloaded bytes must match locked SHA256/size before installation. The reviewed affirmative excerpt must occur in the exact hash-matched notice. Rendering independently calls the same review/byte gate before opening fonts.

A review sidecar is a trusted, maintained decision record, not a text classifier. Matching a quoted excerpt does not by itself prove legal sufficiency: the reviewer must actually inspect the complete notice, applicable grant, asset scope, dual alternatives and any RFN declarations. Deliberately editing a review is a new decision, not routine replay.

## New sources

```sh
PYTHONPATH=src python scripts/acquire.py --create-lock \
  --config configs/new-sources.json --output-lock manifests/new-pending.lock.json
```

The new output must not already exist. Downloads go to a staging tree under `data/acquisitions/`; the schema-2 lock records raw notice identity and `pending-manual-review`, with no selected licence, no usage approval and no guessed RFN names. It cannot inherit the current corpus's decisions. The heading-only regression fixture remains pending even when it includes an apparent RFN.

Before research/rendering, a reviewer must author a new sidecar binding that exact config/lock/version and every exact asset identity. Each local-research approval must name a reviewed selected licence, identify the affirmative grant and notice hash, record reviewer/scope, and explicitly distinguish unresolved RFNs/export/model questions. A changed hash, member, commit, config or schema invalidates the prior review. After the explicit review, use `--config`, `--lock` and `--review-manifest` to verify/replay those inputs. Updating the canonical training corpus requires an intentional new experiment/version; do not replace the original campaign lock or retune its held-out results.
